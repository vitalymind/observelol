# PostgreSQL Database Schema (`SCHEMAS.md`)

## 1. Heroes & Items

All versions of Heroes and Items are immutable and persisted forever in `heroes` and `items`, deduplicated by `content_hash`. The `heroes_active` and `items_active` tables track the currently active `version_id` per canonical `hero_id` / `item_id` for upcoming games.

```sql
-- All immutable versions of Heroes (saved forever, deduplicated by content_hash)
CREATE TABLE heroes (
    version_id   SERIAL PRIMARY KEY,
    hero_id      INT NOT NULL,                        -- Canonical Hero ID across versions
    content_hash TEXT NOT NULL,                       -- Hash of (name, image_url, attributes)
    name         TEXT NOT NULL,
    image_url    TEXT NOT NULL,                       -- CDN URL for hero portrait
    attributes   JSONB NOT NULL DEFAULT '{}'::jsonb,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (hero_id, content_hash)
);

-- Currently active version per Hero for upcoming games
CREATE TABLE heroes_active (
    hero_id           INT PRIMARY KEY,
    active_version_id INT REFERENCES heroes(version_id), -- NULL if disabled/removed for future games
    updated_at        TIMESTAMPTZ NOT NULL DEFAULT now()
);


-- All immutable versions of Items (saved forever, deduplicated by content_hash)
CREATE TABLE items (
    version_id   SERIAL PRIMARY KEY,
    item_id      INT NOT NULL,                        -- Canonical Item ID across versions
    content_hash TEXT NOT NULL,                       -- Hash of (name, image_url, attributes)
    name         TEXT NOT NULL,
    image_url    TEXT NOT NULL,                       -- CDN URL for item image
    attributes   JSONB NOT NULL DEFAULT '{}'::jsonb,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (item_id, content_hash)
);

-- Currently active version per Item for upcoming games
CREATE TABLE items_active (
    item_id           INT PRIMARY KEY,
    active_version_id INT REFERENCES items(version_id),  -- NULL if disabled/removed for future games
    updated_at        TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

## 2. Individual Replays

Finished replays are stored as individual rows containing the replay `id`, `game_id`, creation timestamp, and compressed binary data. `game_id` is unique so worker retries can safely use `ON CONFLICT (game_id) DO NOTHING`.

```sql
CREATE TABLE replays (
    id          BIGSERIAL PRIMARY KEY,
    game_id     UUID UNIQUE NOT NULL,                 -- Game ID (UUIDv7) generated by Dispatcher
    version     INT NOT NULL DEFAULT 1,               -- Replay format version
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    events_data BYTEA NOT NULL                        -- Protobuf + Zstandard compressed events
);
```

## 3. Replay Bundling & Technical Offsets

`replay_bundles` keeps references (`cdn_url`) to bundled replay files stored in the CDN, while `replay_offset` stores the last processed replay offset.

```sql
CREATE TABLE replay_bundles (
    id              BIGSERIAL PRIMARY KEY,
    first_replay_id BIGINT NOT NULL REFERENCES replays(id),
    last_replay_id  BIGINT NOT NULL REFERENCES replays(id),
    replay_count    INT NOT NULL,
    cdn_url         TEXT NOT NULL,                    -- URL to bundle file stored in CDN
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE replay_offset (
    key             TEXT PRIMARY KEY,                 -- e.g. 'replay_bundler'
    last_replay_id  BIGINT NOT NULL DEFAULT 0,        -- Offset in replays(id) for next check
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

## 4. Game Errors

Failed games that do not pass worker consistency or validation checks are recorded in `replay_errors`. Error descriptions and categories are normalized in `error_types`, while `replay_errors` references `error_types.code` and stores structured parameters in `details` (JSONB).

```sql
-- Lookup dictionary for all registered validation & system error types
CREATE TABLE error_types (
    code        VARCHAR(32) PRIMARY KEY,              -- e.g. 'INDEX_GAP', 'CORRUPTED_EVENT'
    name        TEXT NOT NULL,                        -- e.g. 'Index Gap'
    description TEXT NOT NULL                         -- Explanation template
);

-- Pre-seeded error dictionary
INSERT INTO error_types (code, name, description) VALUES

CREATE TABLE replay_errors (
    id          BIGSERIAL PRIMARY KEY,
    game_id     UUID UNIQUE NOT NULL,                 -- Game ID (UUIDv7) generated by Dispatcher
    error_code  VARCHAR(32) NOT NULL REFERENCES error_types(code),
    details     JSONB,                                -- Structured diagnostic parameters
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
```
